## 💻 Cómo arrancar a trabajar (Axel)

### 1. Clonar y preparar el entorno

```bash
git clone https://github.com/dlastra1976/moviendo-leyendas.git
cd moviendo-leyendas
git checkout develop
./scripts/bootstrap.sh
```

El bootstrap levanta el stack de **desarrollo** (hot-reload, puertos
`5173`/`8000`/`5432`). No toca producción.

Verificar en el navegador:
- Frontend: http://localhost:5173
- Backend: http://localhost:8000/health → `{"status":"ok"}`
- Backend: http://localhost:8000/api/v1/hello

### 2. Flujo de ramas

```bash
# siempre partir de develop actualizado
git checkout develop
git pull

# rama por feature / bug
git checkout -b feature/<descripcion-corta>

# commits pequeños, mensajes en español
git commit -m "feat(frontend): agregar página de inicio"

# subir y abrir PR contra develop
git push -u origin feature/<descripcion-corta>
# luego en GitHub: Compare & pull request, base = develop
```

### 3. Frontend (`frontend/`)

- Stack: Vite + React 18 + React Router + TypeScript
- Entry: `frontend/src/main.tsx` → `App.tsx`
- Páginas: `frontend/src/pages/`
- Cliente API: `frontend/src/lib/api.ts` (usá `api.get/post/...`, **no fetch directo**)
- Tests: Vitest + React Testing Library (`*.test.tsx`)
- Build de producción: `npm run build` → sale un `dist/` que nginx sirve.

**Convenciones importantes:**
- Las llamadas a la API usan rutas relativas (`/api/v1/...`) — en dev, Vite
  las proxyea al backend; en prod, Caddy hace el enrutamiento.
- `VITE_API_BASE_URL` se deja vacío para que use el proxy/relative URLs.

### 4. Backend (`backend/`)

- Stack: Node 20 + TypeScript + Fastify + Zod
- Entry: `backend/src/server.ts`
- Config/env: `backend/src/config.ts` (Zod valida las env vars al arrancar)
- Tests: Vitest (`*.test.ts`), setup global en `src/test-setup.ts`
- ORM: **aún no decidido** (pendiente ver si Supabase client, Drizzle o pg directo)

**Convenciones importantes:**
- Las env vars las lee Zod al boot — si falta una o está mal, el server no
  arranca y grita con un mensaje claro.
- La URL de la BD en dev es la que setea `docker-compose.yml`
  (`postgres://cowork:cowork_dev_password@postgres:5432/cowork_dev`).
- CORS_ORIGIN en dev permite `http://localhost:5173`. En prod,
  `https://www.moviendoleyendas.com`.

### 5. Base de datos

- Migrations: `infra/supabase/migrations/*.sql` (se aplican en orden
  alfabético al iniciar el contenedor de postgres).
- Para agregar una migration nueva: crear archivo `YYYYMMDDHHMM_descripcion.sql`
  en ese directorio y `docker compose down -v && docker compose up` para
  recrear la BD desde cero localmente.

### 6. Tests y lint

```bash
# Backend
cd backend
npm test          # vitest
npm run lint      # eslint

# Frontend
cd frontend
npm test          # vitest + RTL
npm run build     # verifica que compila
```

El CI en `.github/workflows/ci.yml` corre estos comandos en cada PR.
